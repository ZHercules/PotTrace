# PotTrace 验收记录

本文件记录前阶段已执行的证据，不将待测项目描述为通过。当前为开发预览，稳定版验收尚未结束。最新开发分支验收见 [develop 合并验证](develop-validation.md)，图内链路证据见 [DirectShow 在线统计](graph-ingestion-validation.md)。

发行候选：`0.1.0-preview.1`，本地自包含 ZIP。最终 Release 检查：57 项托管测试（Contracts 5、Core 30、Storage 11、App 11）、1 组原生行为测试、5 项安装测试全部通过，构建无警告/错误。

## 环境

- Windows 10.0.26300，x64。
- PotPlayer 26.4.22，使用日用播放器；验证在隔离副本中进行。
- .NET SDK 10.0.404 / runtime 10.0.15；MSVC 19.51，Windows SDK 10.0.26100。

## 已通过的真实链路

`verify_callbacks.py`：首次启用后重新启动自动初始化；打开、开始、时间、暂停、恢复、完成、关闭回调收到。暂停 11 秒位置不变。`PlaybackTime(path, durationMs, positionMs)` 参数顺序已实测。

`verify_bridge.py`：正式脚本和 DLL 自动拉起后台，无媒体不产生历史。一次正常显示的 1 倍速场景中，暂停位置 5,301 ms、记录播放 5,219 ms，差值 −82 ms；暂停后记录不增长；保存 1 条有效片段；SQLite 完整性为 `ok`。这是单次条件下的测量，不是所有操作的误差保证。

`verify_lifecycle.py`：两个播放器共享一个后台，形成两个独立有效会话；后台进程异常终止后自动重启并无重复计次；主动退出后 5 秒内没有被重新拉起；手动启动重新连接；最后一个播放器退出后后台退出；暂停统计设置跨重启保持。

`verify_playback.py`：一轮完整流程通过暂停打开、同一区间两次独立记录、仅入队不计入、2 倍速、同文件重新打开。12 秒倍速操作中记录实际播放 11,610 ms，媒体前进 23,996 ms。随后仅启动/暂停场景连续三轮通过，但另一轮曾在 11 秒检查点失败，不能以通过轮次掩盖偶发失败。

对 `0.1.0-preview.1` 另做了实际安装验证：安装到新建的 `out/package-player` 副本，后台使用安装目录中的自包含程序，启动环境移除 `DOTNET_ROOT`。完整播放流程通过；本轮 2 倍速实际记录 12,000 ms，媒体前进 23,992 ms；重复区间保持 2 条，队列未计入，同文件重开后增加一次。日用播放器 未部署。

## 自动化

管理层测试覆盖 10,000/10,001 ms 与 5,000/5,001 ms 严格边界、暂停、倍速、跳转、跨午夜、时钟回拨、采集暂停、热度端点、重放、恢复、真实 SQLite、来源版本、CSV 转义、查询竞态、命名管道及生命周期。

安装测试覆盖自有文件部署、升级保留设置、卸载保留历史、包 SHA-256 校验及只读目标导致升级失败的回滚。

补充实际 SQLite 故障注入：写入失败不返回已提交确认；重放后只计一次；删除失败恢复内存会话与数据库；恢复安全副本不会被下一次恢复覆盖。盘符与共享根目录排除有边界回归。完整导出查询不受界面分页限制。

十万会话/十万片段合成库：汇总 SQL 64.3 ms，最近 1000 会话 SQL 64.1 ms，完整性 `ok`。该测量不包括 JSON 反序列化、WPF 渲染和完整热度计算。深浅主题在本机 150% 缩放下已截图检查；来源选择框显示文件路径。

一次独立整分支审阅发现恢复副本覆盖、盘符根目录排除两项重要问题，均经失败回归复现后修复；未进行重复审阅。不将审阅结果当作未执行场景的测试证据。

## 已知限制及剩余验证

载入暂停替代方案已做[独立能力验证](paused-load-validation.md)：26.4.22 与 26.10.21 的首次、手动切换、真实自然下一集都直接进入播放；最小化暂停先播放约 251–253 ms。注入身份通知延迟 2/8 秒时，实际暂停等待 11 秒只记录 9125/3047 ms。写入确认后自动恢复命令可用，但原子载入暂停及等待完整计入两个门槛失败，未实现产品门控或部署。

2026-11-17 补充调查和修复：见[启动漏计调查](startup-investigation.md)。已修复迟到 Start 无条件写为 Playing 和 Open 继承旧时长；新增回调回归先失败后通过。修复后 Release 57 项托管、2 组原生、5 项安装测试通过，完整真实播放流程与六轮启动复测通过。然而此前已复现的身份迟到条件尚未被消除，正式部署门槛仍未通过，不能把本轮未复现视为根因修复。

- `OnFinalize` 未被可靠观察到；使用管道断开与后台宽限期处理退出。
- 初始脚本回调曾延迟 1.7–8 秒；正常显示启动也有约 2 秒偶发延迟。无法可靠识别媒体之前不补造记录；接近 10 秒的启动边界仍可能漏计。
- 位置接口约每 500 ms 更新；原生采集需容忍缓存量化。倍速为估算；短于采样间隔的往返跳转可能不可见。
- AB/整片循环、系统休眠、更多 Windows/PotPlayer 构建待验证；不能保证禁用脚本后继续切换影片的身份识别。
- 人工合并影片/来源热度未实现；目前同名自动汇总、各来源热度独立。十万条以上完整导出的内存峰值及 100%/200% DPI 待验证。
- 详细会话列表最多展示最近 1000 次，全部记录可导出。当前热度计算加载选中来源的全部有效片段，超大历史仍需优化。
