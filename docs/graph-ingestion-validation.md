# DirectShow 在线统计接入进展（2026-11-17）

状态：**实验链路已在线接入现有宿主/引擎/SQLite，尚未达到部署门槛。** 日用播放器 未部署。以下是本机指定版本/EVR 配置的观测证据，不是所有渲染器和文件的兼容性承诺。

## 已实现的链路

私有视频滤镜 → 实际连接上游 `IFileSourceFilter` 完整路径 → 实际视频输出链的拥有者渲染器 → 异步就绪/位置观测 → `PotTrace_Graph` → `GraphTimeline` 独立 mediaEpoch → 原有命名管道/事务 ACK → 真实统计引擎与 SQLite。

- 状态和位置独立线程，慢位置查询不会遮住载入、暂停和换片的状态观测。
- 生命周期 generation fence 拒绝跨 Pause/Run/NewSegment/Stop 的过期结果；Stop 后终止事件遇暂时背压由工作线程重试，保留原关闭时刻。
- 多个候选拒绝准入，图复用不等于同一影片；同一路径在新绑定重开产生新会话。
- 显式 `SourceMode=DirectShow` 时旧脚本只负责初始化，旧 Open/Start/Pause 不再改写图内会话。
- 原生输入使用有界 MPSC 环队列，满队列标记缺口；不会把采集丢失隐藏成连续播放。数据库沿用提交后确认及重放去重。
- 已知 seek 仅切断播放片段，保留暂停停留；未知观测跨关闭/换片时不补造有效停留。
- 暂停状态先到时，最多等待250ms取得同代次、同来源的已暂停位置，事件时间仍是原状态捕获时间；无法确认则保留未知位置。首段起点使用真实 NewSegment 起点，并且只有后续首次来源/就绪证明可使用，NewSegment 本身不创建会话。

## 尚未通过，禁止部署

1. 图报告的Rate=1仍不能代表实际速度。现已改为采样估计、未知null，连续变速保持同一片段并单独保存事件（见末尾修复记录）；检测确认存在延迟，短促/快速连续变速及较高倍率下的采样缺口仍需覆盖，不能宣称精确捕获每次用户倍率操作。
2. 普通/低帧率阈值及首次源起点已经通过；尾部交付的压力/故障极限、缓冲、长时资源稳定性及睡眠唤醒仍需完整覆盖。当前正常关闭与宿主故障恢复的通过结果不能替代这些场景。
3. 当前采集器仍是实验AX，含大量诊断接口查询；正式模块提取、禁用/卸载、安装器私有滤镜配置与回退尚未实现。不能把实验AX直接安装到日用播放器。
4. 新版26.10.21内置Direct3D11渲染器尚无已验证窗口归属证明，保持不支持/不准入；不自动更改用户渲染器。

## 后续连续性方案审查

采样日志中普通和2倍速的position增量与reference-clock增量相差不足1ms，但暂停期间reference clock仍前进。这只能说明已测端点一致，不能独立证明期间没有seek往返、饥饿缓冲或位置由同一时钟推算。修复已加入canonical clock identity、位置/时钟增量校验和未知倍率null，保留失效标记直到成功交付；不因此放宽未知长区间的计时限制。系统睡眠、缓冲和更广格式验证仍未完成。

## 变速错误根因定位（修复前证据）

本次按用户“查找错误原因”的要求，对已有失败实播 `graph-probe-1794909089103591600` 做分层日志分析和真实协议事件的计时条件复算；未修改产品计时规则，未重新部署。

1. **错误起点是采集倍率的语义假设。** `RendererWatch.h:37` 将IMediaSeeking.GetRate直接作为播放倍率。去掉每阶段前800ms/后300ms的过渡区，以QPC计算，三个阶段的媒体位置速度约1.0000/1.9700/1.0001；图参考时钟速度约1.0000/1.9699/1.0001。但对应193/194/191个合格原生样本的rate全为1。这证明当前播放配置的GetRate值不能直接代表相对真实时间的观看倍率。
2. **分段事件的唯一倍率比较条件没有变化输入。** `GraphTimeline.h:139` 只有在current.rate != f.rate时生成RateChanged。实际观察窗口内只见开始RunBefore和末尾PauseBefore，没有NewSegment，generation一直为13；705条协议事件的倍率全为1，RateChanged为0。传输序号无缺号、来源/epoch各1个、sinkLost/logLost均0。因此这次变速事件缺失发生在事件生成之前，没有证据表明是传输或数据库丢掉了变速事件。
3. **每次采样500ms的误差下限掩盖了错误倍率。** `GraphTimeline.h:141` 与 `SessionTracker.cs:50` 均以max(500ms,预测增量20%)校验位置。实播703个可计算播放区间中，采样间隔中位31ms、最大63ms，按错误Rate=1预测的位置误差最大141ms，全部通过500ms门槛。逐事件复算累计18641ms，与数据库18641ms完全一致。时长接近18656ms操作窗口，不代表倍率与变速边界正确；也不能保证低采样频率或其他倍率同样准确。
4. **引擎测试覆盖与真实输入之间存在缺口。** 既有 `RateChangeCreatesBoundaryButKeepsRealTime` 测试直接提供RateChanged和rate=2，证明下游能处理正确输入，不证明采集器会产生它。此次单独重新执行该测试1/1通过。真实集成用例仍失败，数据库最终只有一段18.641秒、Rate=1的有效明细，符合错误输入经现有逻辑处理的结果。

Microsoft说明标准SetRate描述的媒体位置推进速度以参考时钟为参照：[Setting the Playback Rate](https://learn.microsoft.com/en-us/windows/win32/directshow/setting-the-playback-rate)。本机日志与“通过改变图时钟推进节奏实现实际变速”的解释一致，但没有PotPlayer内部实现证据，不能将该解释扩大为所有版本的已证实机制。NewSegment是来源向下游提供片段时间/速率信息的通知：[New Segments](https://learn.microsoft.com/en-us/windows/win32/directshow/new-segments)；本次变速期间没有观察到它。

该诊断要求区分图内倍率、实际时间下的有效速度和未知倍率，而不是仅缩小500ms容差。以下记录后续实际修复，前述失败证据保留。

## 变速修复与连续片段规则（2026-11-17）

用户确认：连续播放中的变速保留一个播放片段，变速作为片段内事件记录。暂停、seek、位置失效和未知观测仍保守分段；严格>5秒门槛及暂停仅计停留的规则不变。

- 有效速度使用位置/QPC的连续窗口估计，图GetRate仅留作诊断；初始、转换中或失效速度输出null，禁止用1代替未知。
- RateChanged标记估计并携带采样观测窗口；此窗口不是精确操作时间，也不保证包含真实变速起点。片段Rate为平均观测速度，不等于用户指定倍率。
- JSON导出包含Timeline及观测窗口；数据库保留事件、连续片段和原始顺序。
- 针对时钟/位置不一致添加PositionDiscontinuity：切断不可确认的播放，保留已确认停留。慢查询或发布拒绝不能清掉尚未交付的失效标记。
- 审查发现暂停尾部补齐可能忽略失效标记，已用原生反例RED→GREEN修复：原暂停时刻输出未知位置，再传播位置失效事件。禁止用失效位置补计播放尾部。
