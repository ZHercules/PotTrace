# 图内采集接入设计

用户已明确授权：先解决当前影片及载入边界，再接入现有引擎/数据库，完整验证后部署。沿用现有 C++ 采集桥接、协议和 C# 统计/SQLite，不重新选择技术栈。当前为开发设计，验收未完成；正式安装仍禁止。

## 选择与边界

已比较脚本延迟回填、单纯滤镜 Pause/Run、渲染器就绪加实际连接来源。前两者已被实际延迟、异步预滚反例排除。实现方向采用第三者，并保留原生边界；无法确定时输出缺口，不回填匿名状态。

首个支持目标是用户本机原版本及其 EVR 播放配置，必须在实际副本验证。新版 Direct3D11 目前缺乏已验证窗口归属接口，不套用 EVR 规则，不自动更改用户渲染器。若正式目标配置与验证目标不同，不部署。

## 来源和载入证明

- 来源必须来自采集滤镜实际连接的上游 `IFileSourceFilter`，完整本地路径；不能从标题、同名文件、队列或命令行推断。
- 从实际连接的视频输出链取得渲染器及 HWND，检查所属进程、主窗口和唯一候选。枚举失败、多个候选、未知渲染器或来源不一致均拒绝准入。
- 加入图、已连接 Pause、首个压缩样本都不等于就绪。只有渲染器 `GetState(0)==S_OK` 且 Playing/Paused、来源两次读取一致的观测才能开始已确认停留。
- 保留查询起止时间；超过 50 ms 的复合查询作未知，不用结束时读到的身份补到开始时。这个 50 ms 是观测失效上限，不是对实际载入精度的承诺。
- 身份/状态采集与可能阻塞的媒体位置查询分离，位置查询不得遮住暂停/恢复边界。原型已发现首次位置查询可跨越数百毫秒。
- 同一图可能复用于不同路径；每次确定的来源更换产生新 mediaEpoch。暂停、恢复、跳转、变速不产生新打开次数；原生 Stop/销毁清除旧实例。

本阶段尚需证明的视频连接链及边界规则不能仅凭文档宣称成立：必须先用真实首次打开、暂停停留、同名切换、预览、预加载取消及下一集用例检验。

## 接入和统计

原生侧把已确认事件转换为现有 PlaybackEvent，保留真实观测时间、完整路径、独立 mediaEpoch 及递增 sequence。复用现有有界队列、命名管道、提交后 ACK 和 SQLite 检查点；不以另一套数据库导入替代实际在线链路验收。启用图内模式后，旧脚本仅启动/管理桥接，不再改变播放记录，避免延迟事件覆盖新身份。

累计时长按实际播放墙钟计算；暂停只计停留。停留严格 >10000 ms；详细片段严格 >5000 ms；重复时间段独立且按真实时间排序。暂停、跳转、缓冲、缺口、结束必须分段。2026-11-17 用户补充确认：连续变速不分段，改为片段内时间轴事件。相同文件名归并汇总，完整来源分开热区；沿用已批准规则。

不更改阈值来使测试通过。位置不足以确认的播放区间保留缺口，不能伪造时长；如果常规播放仍因此漏记，验收失败，不部署。

## 生命周期与验证

流线程不访问数据库、不等待宿主 ACK、不枚举图；异步工作者持有明确引用，停止后不能继续发布旧来源，退出不得与播放器锁互等。只在隔离副本配置私有滤镜，不注册全局 COM。

先实现并测试原生准入/切换规则，再在线接入测试宿主。SQLite 验收覆盖：暂停超过10秒而播放0、两个独立重复片段及热区次数、同名不同目录切换、下一集、无效文件、重连重放、退出尾部。用命令时刻、原生边界和已知合成媒体核对，不只验证“数据库有行”。

保留未通过项及原始证据；只有准确性、异常恢复与播放稳定性均通过，才发布新包并部署到已验证的本机配置。
