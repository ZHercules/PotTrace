# DirectShow 图内采集隔离验证

> **For agentic workers:** Use superpowers:executing-plans inline. 用户已批准原型验证；只有全部准确性与稳定性门槛通过后才允许部署。

**Goal:** 验证图内组件能否及时、无歧义地识别当前实际影片及载入生命周期，覆盖首开、切换和自然下一集。

**Architecture:** 临时使用微软 DirectShow 基类构建不修改媒体样本的传递滤镜。通过图内 IFileSourceFilter 获取来源，在 Join/Pause/Run/Stop/首样本等边界记录原生单调时间。与原有脚本入口及外部播放器状态对照。日志走有界异步队列，流线程不写文件、不等待后台；只在隔离播放器配置滤镜，禁止全局注册或修改生产解码设置。

**Tech Stack:** Windows SDK、MSVC、Microsoft Windows-classic-samples DirectShow baseclasses、Python/Win32/UIA。

**Spec:** `../specs/2026-11-16-pottrace-design.md` 计时规则及用户本轮批准的图内原型验证。

## 验证任务

- [x] 下载并固定微软基类来源及许可；仅放 out 依赖目录，开发原型放 probes/DirectShowProbe。
- [x] 构建 x64 透明传递滤镜，明确多个来源/路径截断/日志溢出为不确定；不把第一个来源盲当当前影片。
- [x] 在隔离播放器确认私有外部滤镜加载方式，不在系统注册 COM 滤镜。
- [ ] 首次启动、同实例切换、自然下一集：对照完整路径和各边界时间；未连接的构图尝试不得算载入，不能把 Pause/预滚自动当当前媒体。
- [ ] 区分已载入当前图、后台预加载图、普通队列项；测同名不同目录、失败文件和停止/重开，避免串档。
- [ ] 比较未挂载与挂载后的启动、播放、暂停、跳转和结束；若原型影响播放或存在死锁，不进入产品实现。
- [x] 保存证据与明确结论。身份/实际载入时刻/预载归属任一无法可靠确定则不部署；不以早于脚本的通知替代完整准确性验收。

## 本次执行结果

见 [详细验证](../../directshow-validation.md) 和 [结构化证据](../../diagnostics/directshow-evidence.json)。两个隔离版本的三种核心转换取得完整路径，预加载暂停/取消与失败文件恢复通过；这些是取证用例通过，不是剩余三个验收项全部完成。

发现整个图的枚举末尾返回 E_FAIL，保留不确定标记，改为直接查询真实连接的输入来源。EVR 有窗口归属；新版 Direct3D11 渲染器不提供所用标准窗口接口。精确载入时刻、首次即暂停和预览图竞争仍未证明，长期/硬解码稳定性未验收。故停止在隔离原型阶段，不接入正式记录或部署；没有通过降低阈值、猜测时间或强制改变用户渲染器来绕过门槛。

## 时间定义

JoinFilterGraph 仅表示滤镜加入图，不能视为影片已成功载入。Pause 可能为预滚；首样本可能出现在后台预载。候选载入锚点需同时证明图已就绪、来源唯一且属于当前媒体，并与实际播放/暂停状态关联。日志使用 GetTickCount64，避免不同版本脚本时钟差异。原型不生成正式播放历史。
