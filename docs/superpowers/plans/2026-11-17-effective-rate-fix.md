# 变速记录修复计划

> 使用 executing-plans 在现有 implementation 隔离工作树执行；用户已授权修复，沿用准确、稳定、验收前不部署的约束。

**Goal:** 修复GetRate始终为1造成的虚假倍率和缺少变速事件，保留真实播放计时。用户已确认连续变速保留同一播放片段，变速作为片段内时间轴事件。

**Architecture:** 图内报告倍率仅供诊断。使用同来源/代次、同参考时钟的连续位置与QPC观测确认有效速度；所得值明确为估计，不宣称是用户设定倍率。变速事件携带用于采样确认的观测窗口，不能保证真实操作发生在窗口内，也不作为播放片段切分点。连续片段的Rate为平均观测速度。热度仍按实际媒体区间、时长仍按单调时钟。

**Alternatives:** 直接信任GetRate已被实播否定；仅缩小500ms容差会误判跳转；读取私有内存/拦截播放器内部方法不符合稳定性要求。选择有界连续采样确认，初始或失效倍率为未知，未完成稳定性验收仍不部署。

**Constraints:** 不改变>10秒/>5秒阈值；不反推载入时间；不回填未知位置；变速检测为采样确认，有观测窗口，不宣称精确回调。暂停/seek/时钟切换/观测中断重置速率证据。仅使用本机隔离副本生成媒体。

- [x] 原生回归复现始终报告1、实际1→2→1时缺少事件；连续窗口估计覆盖恒速抖动、generation/时钟切换和失联，并回放原失败实播样本。
- [x] 接入采集、图状态机及协议；未知倍率序列化null，标记估计并保留观测窗口；数据库明细保留平均观测速度，JSON导出包含Timeline。
- [x] 托管回归验证真实时长、未知倍率、重复片段、观测窗口；连续变速不切片，短阶段相加超过5秒可入明细。旧版本回退读取null兼容尚未验收。
- [x] 实播复测1→2→1、1→1.1→1、半速/1fps、重复观看、宿主恢复、换片及预加载下一集；严格阈值与真实WPF/热区核对通过。观测停滞触发保守切段的失败项保留，详见验证报告；通过当前修复用例不等同整个产品可部署。
