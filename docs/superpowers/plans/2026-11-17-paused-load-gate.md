# 载入暂停与统计就绪门控验证计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline. 用户已批准本方案，常规验证和实现继续执行；只在全部验收通过后部署。

**Goal:** 首次启动、切换影片及自动下一集都先载入暂停，统计就绪后自动播放；等待期间的真实暂停停留准确计入有效门槛。

**Architecture:** 优先验证 PotPlayer 现有公开设置/控制接口能否在影片开始播放前建立暂停状态。只有入口真实可用后才实现身份确认、持久化确认与恢复播放门控。不把播放后快速暂停当作载入即暂停；不使用固定等待时间冒充就绪确认。

**Tech Stack:** 隔离 PotPlayer 26.4.22 / 26.10.21、Python Win32/UIA 探针；必要时复用 AngelScript、C++ 桥接、C# 状态机和 SQLite。

**Spec:** 用户本轮批准的载入暂停方案，以及 `../specs/2026-11-16-pottrace-design.md` 的计时口径。

## 约束与检查重点

- 所有试验仅修改仓库 out 下的播放器副本；不改变原安装、系统文件关联或用户全局播放习惯。
- 必须捕获第一条可读状态、影片位置变化、完整身份通知时间、统计确认时间；零位置不能单独证明从未播放（位置有缓存）。
- 等待停留从可靠确认的实际载入时刻开始；只有排队、尚未载入的时间不计。不得通过延后门槛起点或默认补齐整段程序时间规避。
- 播放器自动下一集必须验证真实自然结束跳转；人工重新打开不能替代。
- 超时、关闭、切换、用户主动暂停、统计未启用时不得错误恢复播放；每个确认需绑定实例及媒体代次。

## Task 1 — 证明播放器原子载入暂停能力

- [x] 检查本机命令行、语言资源、设置及实际控件，识别有证据支持的入口。
- [x] 新增 `probes/PotPlayerProbe/verify_paused_load.py`，记录实际状态和回调时间；每次运行保留 JSON 证据并恢复测试配置。
- [x] 测首次启动、预先设置暂停后打开、暂停状态下切换、真实自动下一集；控制命令仅发送给测试进程。
- [x] 若只有窗口失焦/最小化暂停设置，单独验证其是否覆盖上述入口；不得将这种设置未经验证等同于载入暂停。
- [x] 能力失败则记录明确反例及覆盖缺口，停止依赖该能力的产品实现，不部署。

**Task 1 结论：未通过能力门槛。** 两版本首次/切换/自然下一集都曾进入播放。最小化设置是播放约 251–253 ms 后暂停。详见 `../../paused-load-validation.md`。Task 2 产品实现依赖未满足；另完成独立受控延迟试验，确认写入后发恢复命令有效，但 11 秒等待在 2/8 秒身份延迟下只计 9125/3047 ms，不能宣称等待计时通过。

## Task 2 — 就绪确认与等待停留（依赖 Task 1）

- [ ] 写失败回归：载入后等待 11 秒，次数 1、播放 0；确认后自动播放；等待期间切换/关闭不错误恢复；重复确认幂等。
- [ ] 建立完整身份及载入时刻的可信关联；匿名窗口不能直接回填到迟到路径。
- [ ] 写入并确认初始会话后恢复播放；实例/代次/当前状态再次一致才发恢复命令；超时保持暂停并提示。
- [ ] 故意延迟确认 2 秒、8 秒，验证暂停等待连续计时、播放时长从实际恢复开始，旧确认不控制新影片。
