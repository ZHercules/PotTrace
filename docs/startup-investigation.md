原版失败样本中，首次观测暂停时刻为 45908687 ms，Open 到达时刻为 45909984 ms。脚本内时间戳与原生入队时间相近。缺失区间发生在可靠完整文件身份到达之前，而不是数据库落盘等待。禁用所有原生工作线程仍能复现，排除了“这些线程是延迟的必要条件”；这不等于已经定位 PotPlayer 内部的具体调度代码。

新版 HostGetTickCount 的实测数值不能直接与原生 GetTickCount64 对齐。各版本不能未经校准共用这两个时钟。

## 本次已修复的独立错误

回调可能按 Open → Pause → Start 到达。原实现忽略尚未激活时的 Pause，又在 Start 中无条件写入 Playing。现在 Start 通过当前状态、位置和时长查询激活；暂停保持暂停，停止或查询失败保持待确认。Open 同时清空旧媒体总时长。

新增原生回归直接执行生产回调状态机，只替换播放器查询边界。五个场景包括暂停先于 Start、Start 到达时已停止、查询超时及恢复、新 Open 清理旧时长、正常播放位置。修改前前四项失败，修改后全部通过。该修复防止虚构播放状态，不恢复迟到的身份区间。

修复后验证：Release 构建无警告/错误；57 项托管测试、2 组原生测试、5 项安装测试通过。完整真实播放流程通过暂停有效打开、同一区间两次独立记录、仅入队排除、同文件重开；倍速实测播放 11734 ms，影片前进 23994 ms。另六轮启动复测全部通过，证据 `out/startup-matrix-1794853291485783500`，均暂停 11 秒，记录停留 10609–10672 ms，播放时长均为 0。

这六轮没有复现长延迟；修复并未改变完整文件身份到达的时机，因而不能据此宣布前述失败条件已被消除，也不能推断严格阈值附近的误差已经消失。

## 不采用匿名缓存直接回填

考虑同名、同长度的两个文件 A 与 B：首次轮询得到暂停、位置零；在 Open 回调交付前用户从 A 切到 B。没有原始事件发生时间和当时的完整媒体身份，就无法证明这些匿名样本属于 A 还是 B。以回调到达顺序、当前位置、窗口标题或启动命令行猜测，会把漏计变为错计。

因此不调低 10 秒门槛，不把整个程序运行时间计为打开时间，不从当前位置倒推播放时间，也不把失败轮次隐藏在平均通过率中。

## 采集入口调整的具体研究方案

现有公开脚本接口不足以通过当前准确性门槛；需要验证独立于迟到脚本通知的媒体身份与生命周期入口。候选是隔离环境中的 DirectShow 观察滤镜：由图内的 IFileSourceFilter 获取来源，关联图的 Run/Pause/Stop 与寻址事件。微软文档说明 [IFileSourceFilter](https://learn.microsoft.com/en-us/windows/win32/api/strmif/nn-strmif-ifilesourcefilter) 可提供加载的文件；[滤镜基类](https://learn.microsoft.com/en-us/windows/win32/directshow/introduction-to-the-filter-base-classes) 可用于实现图内组件。这只说明候选接口能力，不证明 PotPlayer 的所有后端都经过该入口。

原型必须先解决：当前图与预加载图的区分、暂停首开、同路径重开、同名不同路径快速切换、图撤销时的引用释放、线程退出和故障隔离。必须验证内置解码器、硬件加速、有声/无声影片、常用容器及网络媒体的覆盖；不能为获取统计而静默替换用户的解码/渲染配置。若无法无干扰挂接或不能区分队列预加载，该候选也应判定失败。

这属于接入架构变更，当前尚未实现或证明可行。现有统计核心、SQLite、界面与安装代码可复用；不能把候选方案当作可部署修复。

## 再次部署前必须通过

1. 冷启动、正常显示和隐藏启动重复测试；11 秒暂停必须计一次，暂停不增加播放时长。
2. 可控时钟仍严格遵守 10,000/10,001 ms、5,000/5,001 ms；真实链路记录实测误差，不通过降低门槛规避。
3. 同名同长度来源快速切换、同路径重新打开、队列预加载、回调到达前关闭不能串档或虚构时长。
4. 查询失败、事件丢失、后台重连和播放异常应截断不确定区间；禁用扩展的行为应明确验证。
5. AB/整片循环、休眠边界、兼容性及新接入组件的长期稳定性完成后，才更新正式部署结论。

当前结论：保留开发预览，阻止本次正式部署；完整验收尚未完成。
